**Goal:** Make every result land:
- stat deltas float and the pill pops
- the card footer reads your Aura
- negative Aura heals a little each day
- licensed sounds play on cards and results
- your avatar cheers or sits
- walk-ins sometimes come back to back under a BUSY DAY chip

- **Client.** `HUD` owns the floats, the pill pop and the BUSY DAY chip. A new shared client module, `Modules/CardFeel`, owns the footer line, the UI sounds and the avatar reaction, and both card UIs call it.

## Shared shapes (every task uses these names)

- **`Format.AuraFooter(aura: number?) -> string`** (pure). nil counts as 0. Each line is ≤ 58 characters, the length of today's line, which fits the phone footer beside DISMISS:

  | Band | Line |
  |---|---|
  | aura < 0 | `"Your Aura's in the red. People hesitate. Odds stay hidden."` |
  | 0 ≤ aura ≤ 299 | `"Your Aura and Followers tilt the odds. You never see them."` (today's line) |
  | aura ≥ 300 | `"Your Aura's loud. People lean in. Odds stay hidden."` |
- **`CareerRules.HealAmount(aura: number, max: number) -> number`** (pure): `aura < 0` → `math.min(max, -aura)`, else 0.
- **`WalkInRules.RushGap(rush: Rush?, cfg: RushCfg, gap: {number, number}, draw: (lo: number, hi: number) -> number, roll: () -> number, allowStart: boolean) -> (seconds: number, rush: Rush?)`** (pure). `draw` follows the module's `rng(lo, hi)` convention (Plant's).
  - Types: `Rush = { left: number, saved: number }`; `RushCfg = { Chance: number, Size: {number, number}, Short: {number, number} }`.
  - **No rush:** if `allowStart and roll() < cfg.Chance`, start one with `left = draw(cfg.Size[1], cfg.Size[2])`, `saved = 0` and take the burst branch. Otherwise return `draw(gap[1], gap[2])` and nil.
  - **Burst branch** (`left > 0`): `g = draw(gap[1], gap[2])`, `s = draw(cfg.Short[1], cfg.Short[2])`, `saved += g - s`, `left -= 1`. Return `s` and the rush.
  - **Quiet branch** (`left == 0`): return `draw(gap[1], gap[2]) + saved` and nil.
  - For every burst that finishes, its k short gaps plus its quiet gap equal the k + 1 normal gaps they replace, so the long-run pace is unchanged. When the cap, a Reset or leaving ends a rush early, its `saved` is dropped.
  - It never mutates the caller's table.
- **`Config.WalkIns.Rush = { Chance = 0.15, Size = { 2, 3 }, Short = { 10, 20 } }`.** Short gaps are presence seconds after the previous card closes, so the next visitor starts walking 10–20 s after your choice. The result card shows for 8 s.
- **`Config.Career.Sources.AuraHeal = { aura = { max = 5, dailyMax = 1 } }`.**
  - Amount: `CareerRules.HealAmount(aura, 5)`.
  - Paid through `Career.Add(p, "aura", n, "AuraHeal")`; the gate counts it as `careerLog.count["AuraHeal.aura"]`.
  - Toast: `"the internet forgot. +" .. n .. " AURA"`, through the existing InteractionEvent "Toast" path (DataService.lua:187 sends one).
- **Player attribute `BusyDay`** (bool, server-set): true from the re-arm that starts a burst until the re-arm that arms its quiet gap. It stays set while the player is outside the hub: the burst pauses with the presence timer and resumes on return. It is cleared by any of these:
  - WalkIns `Reset`
  - leaving
  - any re-arm that finds `today >= DailyMax`
- **ResultPayload gains `planted: boolean?`.** It is true when this outcome's `Rules.Plant` returned an entry:
  - WalkIns apply's follow-up plant or its first-HIT `mom_plaque` plant
  - Phone apply's plant

  It is not a chip, so t43's chip sums don't change.
- **`Config.SFX` new keys:** each is `{ id = "rbxassetid://N", volume }`, from Task 0's shortlist (`research/wave1b_sounds_2026-10-28.md`).

  | Key | Sound |
  |---|---|
  | `CardOpen` | soft riser |
  | `Win` | ding |
  | `Loss` | thud |
  | `Money` | register ching |
  | `Plant` | blip |
  | `PhoneBuzz` | phone buzz |
- **Hooks (`_StudioWalkInHook`):**
  - `Rush(uid, k)` with k ∈ {2, 3}: the next re-arm starts a burst of k, whatever the test hold (the hook sets the rush directly).
  - `Rush(uid, 0)`: clears the rush and `BusyDay`.
  - `Rush(uid)`: returns `{ left, saved, busy }`, or nil.
  - `Heal(uid)`: runs the heal attempt now and returns the amount paid. It ignores the test hold and the session memory, but not the reward gate.
- **Client test attributes on `OK_UI`:**
  - `Floats`: count (existing).
  - `LastFloat`: text.
  - `FloatLog`: the last 12 floats as `stat|text|x|y` joined by `;`. stat is empty for +XP and +$, and x, y are the label's offset position in OK_UI.
  - `Pops`: count. `LastPop`: the stat.
  - `LastSound`: a `Config.SFX` key. `Sounds`: count. `SoundLog`: the last 12 keys joined by `,`.
  - `LastReaction`: one of `"cheer"`, `"sit"`, `"skip:off"`, `"skip:dead"`, `"skip:seated"`, `"skip:daw"`, `"skip:r6"`, `"skip:moving"`. They are checked in that order, first match wins (after the two outcomes): skip:off (a half Task 0 found the engine doesn't support), skip:dead, skip:seated (`hum.SeatPart`), skip:daw (the caller's `dawUp`), skip:r6, skip:moving (airborne: `FloorMaterial == Air`, or the state is Jumping, Freefall or GettingUp; or a cheer the Animate script refused: its `PlayEmote` returned false or errored).
- **Float labels** carry the attribute `Stat`: `"aura"`, `"followers"`, `"placements"`, `"hits"`, `"sponsors"`, or nil.
- **`UITheme`** gains:

## Rulings in this plan

Each is a call the design leaves open, or a fact the code forced. The user can override any of them; Task 7 lists them all in the report.

- **Floats for stats without a pill.** Placements, Hits and Sponsors float in the Aura pill's column, in their chip colour. Only Aura and Followers have pills (HUD.lua:61-62).
  - Cost if wrong: one column choice.
- **The pill pop is a ring, not a resize.** Each pill gets a child `Pop` frame: a stroke in the stat's colour, with a transparent fill. Its `UIScale` tweens 1.0 → 1.08 → 1.0 while the stroke fades in and out.
  - Why: scaling the pill or the Career frame would move the phone icon, the cypher Bar and the phone card mid-tween (codemap-gaps hazard c).
  - Cost if wrong: the pop reads as a flash around the pill rather than a swell of the pill.
- **Float columns.** Each float goes under its pill. A chain starts at the pills' bottom + 30 in OK_UI space (the BUSY DAY chip's row is always kept free, so floats never jump and the chip never lands on one): y 66 side by side, y 96 stacked.
  - Floats chain by column x, with 6 slots per chain. Side by side, the columns are x 350 and x 470. Stacked, there is one chain at x 350.
  - Today's +XP and +$ floats join the Aura column.
  - Why: this removes the 4-slot wrap that a delivery overruns (codemap-gaps hazard d).
  - Cost if wrong: side by side, +XP and +$ sit at y 66 instead of 72; stacked at y 96.
- **Floats stay under the cards.** Floats stay in OK_UI (DisplayOrder 0), so on phones an open phone card or walk-in result card covers most of them. The card's own result chips show the same amounts at the same moment, and the pill pop stays visible above the card.
  - Cost if wrong: on phones a result lands through its chips and the pop, not a visible float. A separate float gui above the cards is the alternative.
- **Follower float text** uses the result chip's formula: `(d > 0 and "+" or "-") .. Format.Count(math.abs(d)) .. " FOLLOWERS"`, so +1500 reads "+1.5K FOLLOWERS", like the pill and the chip.
- **BUSY DAY chip.** A 92×20 gold label inside the Career frame, 4 px under the pills: at (350,40) side by side, as in the mockup, and at (350,70) stacked.
  - Career grows by 24 px while it shows, so every gui that reads Career makes room.
  - It hides while the cypher phase isn't idle (`RS.OK.Cypher` attribute `Phase`). The under-the-pills cypher Bar sits at y 74, and walk-ins are held during a cypher anyway.
  - It stays up while you're outside the hub, because the burst resumes when you come back.
  - Cost if wrong: on phones, an open phone card starts 24 px lower during a burst; a player in THE HALL sees the chip although no one is coming until they return.
- **Back to back is 10–20 s, not near-zero** (design §4.5). Short gaps count presence seconds after the card closes, and the next visitor then walks about 6–11 s, so the next card opens about 17–32 s after your choice.
  - Why: a gap under the 8 s result card (WalkInUI RESULT_SECONDS) would open the next card over the still-visible result.
  - Cost if wrong: one Config pair (`Rush.Short`), plus the literal in rush_spec and t60a's 10..20 bounds.
- **Rush pulls visits forward** (design §4.5 says the average pace stays the same). Over time the pace is unchanged, but a session that ends before the day's cap sees more walk-ins: about 6.6 instead of 6.2 a day at 1,800 presence seconds. At the cap there is no change.
  - Cost if wrong: a lower `Chance`, or the quiet gap placed before the burst.
- **No burst from a no-pick re-arm.** The re-arm that runs when no card is eligible passes `allowStart = false`, so the chip never promises visitors the deck can't send. A running burst continues.
- **The heal trigger.** The heal fires after the walk-in loop's first 5 s of hub presence each UTC day, once per session. The reward gate's `dailyMax = 1` then holds it to once a day across sessions.
  - Why: "first hub entry of a new UTC day" (design §4.5) needs a signal that also fires for a player who stays in the server past midnight. The spawn pad is inside the hub (codemap-gaps), so the trigger also covers joining. The 5 s delay keeps the toast after ClientMain has connected its handlers.
  - Cost if wrong: the heal comes 5 s into a session.
- **The heal doesn't use the walk-in day rollover** (design §5 says it "reuses" it). Five paths move `prof.walkins.day` (codemap-heal-avatar), so the gate's own careerLog day is the reliable once-a-day rule.
  - Cost if wrong: none to saves.
- **Toast amount.** The toast says the amount actually healed, 1–5. The design's "+5" assumed a player at −5 or below.
  - Cost if wrong: copy.
- **Sounds.**
  - Riser: when a card first shows, once per token.
  - Win or Loss: on a win or loss result. A neutral result plays nothing.
  - Money: 0.25 s later, when the result has a chip of kind `money` whose label starts with "+".
  - Plant: 0.5 s later, when `planted` is set.
  - PhoneBuzz: when a pop arrives.
  - Arrival news counts as a result when its card first shows.
  - Nothing plays while the HUD mute (`MuteMonitors`) is on. The anti-goal "the phone nags" makes quiet the safer default.
  - Delivery money doesn't ching, because it has its own pay screen.
  - Cost if wrong: one switch per rule in CardFeel.
- **Avatar reaction.** It runs client-side on your own character; an owner's emote and Sit replicate to the others.
  - Win: the default Animate script's cheer on R15, `char.Animate.PlayEmote:Invoke("cheer")` in a pcall. That is the `/e cheer` chat path, and it plays Roblox's own cheer animation (507770677, track name `CheerAnim`). `Humanoid:PlayEmote` can't be used: it only plays emotes in the avatar's own description, and Task 0's probe showed a test avatar with no cheer there (`research/wave1b_probes_2026-10-28.md`, P2).
  - Loss: `Sit = true` for 2 s on R15. Only the same reaction token releases it, only on the character it started on, and only when no seat holds you.
  - R6 gets neither, only the walk-in tag (design: "R6 avatars only get the tag").
  - Skips, in the order in Shared shapes: you're dead, seated, the beat maker is open or the cutaway runs, R6, or airborne. A caller also passes `dawUp = true` for 1 s after its beat maker or cutaway closes, so a result that shows itself right after `restore()` unseats you never sits you on the floor by the chair.
  - Phone DM and NEWS results react too (design: "on a win … on a loss"). They have no overhead tag.
  - Cost if wrong: phone results stay silent on your avatar.
- **Rush and the phone.** Every re-arm draws through `nextGap`, the E2 one included, and while a DM holds the timer during a burst, the timer is floored at the short minimum (10 s). So a DM opened between burst cards always leaves at least a short gap after its choice, and the burst continues after it.
  - Cost if wrong: a burst occasionally continues after a DM.
- **The icon re-shake** (1a carry-in): every 12 s instead of 4 s while a pop waits. The user hasn't said yet; 12 s keeps the reminder and stops the constant pulse. t57d's window grows to 14 s.
  - Cost if wrong: one constant.
- **The duplicated card helpers** (1a carry-in). 1b's new card behaviour goes into one shared module (`CardFeel`) instead of being added twice. The ~70 lines 1a copied stay as they are, which keeps 1b off code it doesn't need.
  - Cost if wrong: the old copies remain a later cleanup.
