# Day One in Your Bedroom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers write files and run CLI specs only; the controller is the only Studio client.

**Goal:** A new player's first minute is a chain of choices in their own bedroom: JUNO VALE's beat request the moment they wake up, then "play it on your speakers?", then "spend it?", then the random starter visitor at their door. It replaces the passive tour tracker as the way in; the tracker stays as a small DAY ONE pill with SKIP.

**Architecture:**
- **Pure first.** `Modules/DayOneRules` (new, pure) decides which card comes next from `prof.tour`, the haggle, the one-time bonus, the walk-in hold and the fills. `Data/DayOne` (new, pure data) holds every word. Both are CLI-tested.
- **One server owner.** `Systems/DayOne` (new) runs the chain: it starts once you wake up, sends cards on its own remotes, acts on the choices and ends the tour. `Systems/Rooms.lua` is not touched (flagged twice at ~950 lines).
- **Existing systems change at named seams:**
  - `Tour`: a `Changed` event, `Finish(p)`, the room lines in its client payload, and the done toast.
  - `WalkIns`: the `DayOneBusy` hold in `tick` and `schedule`, and `ArmFirst(p, s)`.
  - `Contracts.Delivered`: a 5th argument, the delivered beat.
  - `Gear.OpenFor(p, inst)`, the rack handler's body, exported.
  - `DAW.OpenFor(p, inst, seat, opts)`: `opts.presets` opens the preset chooser.
- **The client reuses the walk-in card.** `Modules/WalkInUI` also draws Day One cards: their own remote, header and SKIP label, and a `now` card shown over the beat maker. `Modules/TourUI` becomes the DAY ONE pill that points at your bedroom laptop. `Modules/CoachUI` (new) adds coach marks found by name on the live beat-maker controls; `Modules/DAWUI` stays untouched, as it is Aku's area.

**Tech Stack:** Luau (Roblox), Roblox Studio via the built-in Studio MCP (`tools/mcp_call.py`), `tools/sync.py`, `tools/test.py`, `sh tools/spec.sh`, the `luau` CLI.

**Spec:** `plans/2026-11-05-wave3-stakes.md` "### Task 5e: Day One" (the decided chain, 11-06). `specs/2026-11-12-progression-and-rooms-design.md` §4.9 (it all happens in your bedroom), §4.0 + §7 D10 option C (card 2 is "play it on your speakers"; airing in the studio comes next; "spend it?" uses the rack that opens from your laptop), §7 D3 (the first card is JUNO VALE's beat request; you choose, then you're straight in the beat maker) and §7 D13 (the grace rule, this plan's pacing fallback). The rooms core this stands on: `plans/2026-11-12-your-rooms.md` Tasks 2, 3, 5, 6, 7 (ledger `.superpowers/sdd/2026-11-12-your-rooms/progress.md`).

## Shared shapes

  ```
  Config.DayOne = { Enabled = true, FirstCard = 1, WakeWait = 20, LookAround = 30, ReturnMin = 15, HoldMax = 70, CardSeconds = 180,
    AfterDeliver = 3, AfterSpeakers = 4, VisitAfter = { 5, 7 }, HaggleOdds = 50, HaggleBonus = 50, PrivateXP = 10 }
  ```
- **Data/DayOne** (Task 1, words from Task 0):
  - `Header` ("DAY ONE") and `Skip` (the cards' bottom button)
  - `Cards.dayone = { name, tag, line, face = true, choices = { { key = "make", text }, { key = "haggle", text }, { key = "look", text } } }`
  - `Cards.speakers = { name, tag, line, face = false, now = true, choices = { { key = "speakers", text }, { key = "private", text } } }`
  - `Cards.spend = { name, tag, lines = { tool, none }, face = false, choices = { { key = "rack", text }, { key = "save", text } } }`
  - `Toasts = { haggleGood, haggleBad, far, farHub, speakers, speakersRefused, private, rackFar, done }`
  - `Steps[id] = { hub, room }` for the tracker; `Marks[id] = text` for the coach marks
  - Tokens: `{artist}`, `{pay}`, `{ask}`, `{money}`, `{tool}`, `{toolprice}`, `{goal}`, `{goalprice}`, `{goalfollowers}`, `{xp}`, `{reward}`, `{reason}`.
- **DayOneRules (pure):**
  - `Next(tour) -> "dayone" | "speakers" | "spend" | nil`. It is nil when `done`. The first missing of take → "dayone", deliver → nil (you're making the beat), monitors → "speakers", gear → "spend". "open" is never read.
  - `Starter(briefs) -> brief?`: the one with `starter = true` (j1).
  - `Haggle(roll, odds) -> "good" | "bad"` (good when roll·100 < odds).
  - `Bonus(d1, briefId, starterId, first, amount) -> n`: amount only for good, unpaid, the starter, and the first time; else 0.
  - `Holds(chain, now, cfg) -> bool`: not `chain.done`, and either a card is open or pending, or `now - chain.started < cfg.HoldMax`.
  - `Due(chain, now, cfg) -> "return" | "expire" | "send" | nil`, in that priority order:
    - "expire": the open card is ≥ `CardSeconds` old, or it is the returned card 1 and `now - chain.started >= HoldMax`, so a wanderer's first visit isn't held past ~90 s
    - "send": `chain.pending.at <= now`
    - "return": `chain.returnAt <= now` and not `chain.returned`
  - `Tool(gear, owned, money, level) -> row?`: the cheapest unowned row with a `feature`, price ≤ money, `level` ≤ level. This is DayOneFloor's buying rule.
  - `Fill(text, vars) -> text, left`, where `left` is true when a `{token}` stays.
  - `Card(id, data, vars) -> payload`, built as `{ token?, source = "dayone", header, walk, now, card = { id = "day1_" .. id, visitor = { id?, name, style, color? }, tag, line, choices = { { text } } } }`.
    - `visitor.id` is `"juno"` only when `face`, so VisitorFigure draws a generic figure in JUNO's Data/Artists colour.
    - Every text is filled.
    - "spend" picks `lines.tool` when vars has `tool`, else `lines.none`.
  - `Repair(d1) -> d1`.
- **Chain memory (Systems/DayOne, per player, never saved):**
  - `{ started, card = { token, id, at }?, pending = { id, at, beat? }?, returnAt?, returned, room?, beat?, done }`
  - `room` is the room Model of the delivery laptop; `beat` is `{ pattern, bpm, swing }`.
- **Systems/DayOne (server):**
  - `Choose(p, token, index) -> { ok = true } | { ok = false, reason = "stale" | "invalid" }` (DayOne_Choose). Index 0 is SKIP.
  - `Get(p) -> payload?` (DayOne_Get).
  - `Running(p) -> bool`.
  - The player attribute `DayOneBusy` (`Holds`).
- **Remotes** (`build/20_day_one.lua`, idempotent, `OK_Build = "20_day_one"`):
  - RemoteEvent `DayOne` (server → client): `"arrive"` with the payload above, `"leave"` with `{ token }`
  - RemoteFunctions `DayOne_Choose(token, index)` and `DayOne_Get()`
- **Hook** `ServerScriptService.OK._StudioDayOneHook` (Studio and running), `hook:Invoke(cmd, uid, a, b)`:
  - Starting and showing:
    - `Joined` runs the real join path: "held" under the hold, "done" for a finished tour, else "waiting".
    - `Start` starts a chain now, past the hold, and returns Next's id or nil.
    - `Show(id)` starts a chain if none runs, then sends that card now, for staging. A "speakers" card takes its beat from the chain, else `Contracts.Recent(p)[1]`.
  - Choosing and reading:
    - `Open` → `{ token, id }` or nil.
    - `Choose(index)` runs `M.Choose` on the open token; `ChooseToken(token, index)`.
    - `State` → `{ d1, next, busy, card, pending, returned, started }`.
    - `Sent` returns DayOne's actions since the last read, each `{ kind = "arrive" | "leave" | "toast" | "opendaw" | "opengear" | "play", id?, token?, text? }`.
  - Clocks and rolls:
    - `SetRoll(r)` fixes the next haggle roll.
    - `Age(s)` moves every chain clock `s` back. `Tick` runs one loop step now.
  - `Reset` closes any open card, clears memory and `DayOneBusy`, and sets `prof.tour.d1 = nil`.
- **Seams in existing systems:**
  - `Tour.Changed` (player, what), where `what` is a step id, "done", "skip" or "reset".
  - `Tour.Finish(p)` advances every missing step in order.
  - `WalkIns.ArmFirst(p, seconds) -> bool`: true when it set the timer, which needs a ready profile, count 0 and no visit in flight.
  - `Contracts.Delivered` (player, brief, stars, first, beat).
  - `Gear.OpenFor(p, inst)`.
  - `DAW.OpenFor(p, inst, seat, opts?)`: `opts.presets` puts `presets = true` on the OpenDAW payload.
