## How to read this doc

**Every player-facing line sits in a table row** with an id (`1.7`), where it lands, its kind, and the exact text in backticks. A literal `\n` inside a row is a line break on a two-line sign. The Lua blocks in §2, §4 and §9 are paste-ready for Tasks 4, 7 and 1.

**Tokens.** Cast display names only ever come through `{name:<id>}`, and this doc needs none, so none appears below.

| Token | Filled by | Note |
|---|---|---|
| `{player}` | the room owner's display name (`OwnerName`, else `Player.DisplayName`) | A real player, never a cast member. The plan's drafts wrote `{name}`; it is `{player}` here so nobody reads it as a WalkInRules token. In a **toast** a name longer than 10 characters is cut to 9 plus "…", so a 20-character name still fits the toast label |
| `{slot}` | the plot's slot as two digits ("07") | The brief's "STUDIO 07" is slot 7 |
| `{MODE}` | a door mode's label, §10.1-10.3 | CAPS |
| `{gear}` | a gear's `name` from `Config.Gear`, upper-cased by code | §5.7 only |
| `{title}` | a weekly single's title from `DailyRequests.WeeklyTitles`, upper-cased by code | §7.4 only |
| `{used}` `{limit}` | the room's placed count and item limit | §6.6 |
| `{day}` `{artist}` | `LifeRules.DiscoText` fills them (existing) | §7.1-7.3 |
| `{reason}` | a refusal code, in a fallback line | §4.9 |
| `{sponsor}` | the existing sponsor token that `WalkInRules.Fill` fills | §5.3 |

**Case and length by surface.** The scan (appendix) checks each row against its kind.

| Kind | Case | Budget |
|---|---|---|
| SIGN, PLATE, NAME, LABEL | CAPS (tokens excepted) | a sign is at most 2 lines; a button label is at most 14 characters |
| ACTION, OBJECT (prompts) | sentence case, like `Modules/Interactions.lua` ("Open gear rack", "Gear rack") | Action ≤ 20 ("Door: FRIENDS ONLY" is 18), Object ≤ 18 not counting a `{player}` |
| TOAST | lowercase sentences, or a CAPS tag ("NEW GEAR: …"). One sentence has no full stop; two keep theirs | about 40 characters after the fill, 42 at most (the toast label is 360 px, one line, size 16) |
| GEARNAME, ITEM, DESC | names are mixed case like `Config.Gear` ("Roll FX", "Pluck voice"); a desc is a sentence fragment with no full stop | a name ≤ 16; a desc ≤ 50 (the Gear row truncates at the end) |
| STATUS, SENTENCE, HINT | sentence case. A SENTENCE or HINT ends with a full stop | ≤ 40 on the edit bar; a status line ≤ 64 |
| TEXT (a result card's text) | sentence case | about 85 characters after the longest name fills (the label is 312 × 30 px at size 12: two lines) |
| BUBBLE | lowercase | one or two short sentences |
| EXISTING | whatever the code already says | listed so the later task has the format; already approved |

The game is not branded OK, and it never says WEGONEBEOK, OK STUDIO, OK BEAT MAKER, "PROD. OK", CRED/Cred (money is Money), STUDIO TWO, the real studios the game's rooms were rebuilt from, or a BLOCK-list word. The plain word "ok" is fine. The scan appendix lists the exact patterns.
