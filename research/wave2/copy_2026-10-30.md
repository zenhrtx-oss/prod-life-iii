## 1. The four tier visits

These are system-planted walk-in follow-ups, like `mom_plaque` and `sponsor_drop`. A tier's first crossing (through `Career.Add`) plants its visit at `{1, 2}`. A move across several tiers at once staggers them at `{1, 2}`, `{2, 3}` and so on (A4). The scratch sim planted every tier at `{1, 2}`; that difference is too small to matter for the numbers. Each visit is **resolve only**: the news is rolled on arrival and there are no choices. It never costs anything and never loses; the bad outcome is a smaller win with tone `neutral`.

Payouts go through the walk-in path (`AddCred(p, n, "WalkIn")`, `Career.Add(..., "WalkIn")`): money, Followers, and Aura on ICON only (A5). There is **no Placement, no XP and no hits**.

| Tier | Follow-up id | Visitor | Why this visitor | Good (key) | Bad (key) | Odds |
|---|---|---|---|---|---|---|
| BUZZING (1,000) | `tier_buzzing` | `fan` (existing) | the first real fan shows up | $300, +1,000 Followers (`shirts`) | $150, +500 Followers (`stickers`) | 60 |
| KNOWN (5,000) | `tier_known` | `booker` (existing; the design's pick) | late-night TV notices you | $400, +1,500 Followers (`houseband`) | $200, +500 Followers (`bumper`) | 60 |
| FAMOUS (20,000) | `tier_famous` | `blogger` (existing) | the vision's "gossip page" at FAMOUS | $500, +2,000 Followers (`cover`) | $250, +1,000 Followers (`sidebar`) | 60 |
| ICON (100,000) | `tier_icon` | **`labelboss` (new)** | the vision's "label deals" at ICON | $600, +40 Aura, +2,000 Followers (`imprint`) | $300, +20 Aura, +1,000 Followers (`handshake`) | 60 |

- **Aura.** BUZZING, KNOWN and FAMOUS pay Aura 0 (A5).
- **Brief limits.** Money is at most $600, Aura at most 40, and Followers at most 2,000.
- **Odds.** 60 plus the odds bonus (up to +25) means a good outcome about 64–85 % of the time: near the low end at BUZZING, with little Aura and only +1 for Followers, and 85 % only once the bonus is full.
- **Tags.** No visit's text quotes `$N`. The result tag shows the first amount in `TagFor`'s order, which is Followers, not the money: `+1K FOLLOWERS` on a good BUZZING visit. ICON's tag shows its Aura. The chips still list the money.

### Why FAMOUS is the blogger, not the manager
`manager_offer`, `famous_stadium` and `famous_label` already bring the manager at 20,000 Followers. A second manager visit at the same line would repeat him. The blogger is the vision's "gossip page", and her "cover story" is a new moment.

## 4. Story templates

**Format.** Every line renders as `DAY {day} · <sentence>`. The sentences are the game's voice: sentence case, with CAPS only for game words (THE HALL, HIT, LEVEL, the tier names) and for display names.

**Fields and names (A15, A8).** Story entries are named-field records, `{ d = day, k = kind, v = id?, s = sponsorId?, key = string?, n = number?, first = true? }`, and never prose. Names are filled at render:
- walk-in visitors from the roster names `Career.State` sends
- sponsors through `SponsorName(s, roster)`, never the rep's `{sponsor}` template
- session artists through `Data/Artists.ArtistById[v].name`

`StoryFirst` replaces `Story` when the entry has `first = true`, meaning the same event ticked that kind's first.

```lua
C.Story = {
	placement = "You landed a placement with {artist}.",
	hit = "You got a HIT with {artist}.",
	sponsor = "You signed with {sponsor}.",
	sponsor_drop = "{sponsor} dropped you.",
	delivery = "You delivered a session for {artist}.",
	delivery3 = "You delivered a three-star session for {artist}.",
	beat = "You saved a beat.",
	hall = "THE HALL opened for you.",
	legend = "You bought the Legend nameplate.",
	cypher_win = "You won a cypher.",
	level = "You reached LEVEL {level}: {rank}.",
	streak7 = "You hit a 7-day streak on the dailies.",
	tier = "You hit {tier} at {followers} followers.",
}
C.StoryFirst = {
	placement = "You landed your first placement, with {artist}.",
	hit = "You got your first HIT, with {artist}.",
	sponsor = "You signed your first sponsor: {sponsor}.",
	delivery = "You delivered your first session, for {artist}.",
	delivery3 = "You delivered your first three-star session, for {artist}.",
	beat = "You saved your first beat.",

}

C.Loading = "Loading..."
```

| cypher_win | none | none | `BeatBattles.reveal` (a win) |

Notes for the builder:
- **No brief title in deliveries.** The `delivery` lines name only the artist. Daily and weekly briefs are generated (`DailyRequests`, ids like `d20261030_1`), so their titles aren't in `Data/Artists.BriefById`. - **A three-star delivery logs one `delivery3` line.** If either first is missing, it ticks both the `delivery` and `delivery3` firsts.
- **What to log (a recommendation, not decided).** Log `beat` and `cypher_win` only when they are firsts, and log deliveries only on a session's first delivery. A day can hold 3 dailies, sessions and 8 walk-ins, and the ring is 100 lines.
- **Every kind still has a template,** as the brief asks.
- **Sample renders, both rosters.** I filled every template, both sets, with real roster names (`scratchpad/w2t0/render.lua`): 48 lines, and **none contains `{`**. Examples:
  - parody: `DAY 12 · You landed your first placement, with LIL NAV X.`

## 6. Titles

These are ordered rules, and **the first that holds wins**. The auto title shows on the profile card only.

Rule keys:
- `tier = i` holds when the highest tier index reached is at least i (`Config.Life.Tiers`: 1 LOCAL, 2 BUZZING, 3 KNOWN, 4 FAMOUS, 5 ICON).
- `first = id` holds when `firsts[id] ~= nil` (a backfilled 0 counts).
- A rule with neither always holds.

```lua
C.Titles = {
	{ tier = 5, title = "ICON" },
	{ tier = 4, title = "FAMOUS" },
	{ first = "hit", title = "CHART MAKER" },
	{ tier = 3, title = "WELL KNOWN" },
	{ first = "sponsor", title = "SPONSORED" },
	{ first = "cypher", title = "CYPHER CHAMP" },
	{ first = "placement", title = "ON THE RECORD" },
	{ tier = 2, title = "BUZZING" },
	{ first = "delivery", title = "SESSION REGULAR" },
	{ title = "NEW IN TOWN" },
}
```

**Disjoint from `Config.Ranks`.** I compared with spaces removed and upper-cased (A15), and also refused any title that *contains* a whole rank (so `STAR PRODUCER` would fail on PRODUCER). There are **0 collisions** across the 10 titles. Controls: `HIT MAKER` trips as equal to HITMAKER, and `STAR PRODUCER` trips as containing PRODUCER. `CHART MAKER` (the design's word) passes: `CHARTMAKER` is neither a rank nor contains one.

`TitleFor` always returns a string with this list, because the last rule is a catch-all. Drop `NEW IN TOWN` if you'd rather show no title for a brand-new player (then `TitleFor` returns nil).

## 7. Ribbons

Ribbons are cosmetic only. They are earned once, saved with the career day (`ribbons[id] = day`) and never removed, even when the stat later falls.

Rule keys: `first = id`, `tier = i` (as in titles) and `count = stat, n = k` (when `counts[stat] >= k`; `counts` is `prof.career`).

```lua
C.Ribbons = {
	{ id = "streak7", label = "7-DAY STREAK", rule = { first = "streak7" } },
	{ id = "placements10", label = "10 PLACEMENTS", rule = { count = "placements", n = 10 } },
	{ id = "hit", label = "CHARTED", rule = { first = "hit" } },
	{ id = "sponsor", label = "BRAND DEAL", rule = { first = "sponsor" } },
	{ id = "icon", label = "ICON", rule = { tier = 5 } },
}
```
