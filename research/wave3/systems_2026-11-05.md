## 1. Card data shape (D)

D has `W.Visitors`, `W.Sponsors`, `W.Cards` (l.106), `W.Followups` (l.1798), `W.WaitLines`, `W.NoteLines`, indexes `VisitorById/SponsorById/CardById/FollowupById` and `W.Deck = { cards, followups, sponsors(floors), visitors }` (l.2127-2136). The phone and walk-ins share the one `W.Cards` list; a card is a phone card when `source = "phone"` (28 such cards, l.1438-1790; phone follow-ups are in `W.Followups` with `source = "phone"`, l.2084+).

Card fields (all seen in D or read by Rules/WI/Ph):
- `id` (string, unique), `visitor` (id in `W.Visitors`), `tag` (caps header, may hold `{sponsor}`), `line` (his opening bubble), `choices` (list).
- Optional: `source = "phone"` (default "walkin"), `app = "MESSAGES"|"STUDIO"|"NEWS"` (phone only), `news = true` (phone NEWS card: one `sure` choice applied on arrival), `sponsor = "<sponsorId>"` (rep card; needs Aura >= sponsor floor), `when = "unsponsored"|"sponsored"`, `first = true` (picked when visits==0), `minCount` (walk-in count gate), `weight` (default 1), `aired = true` (needs a beat aired this session), `needs = { stat = n }`, `under = { stat = n }`, `cap = { group, per = "day"|"week", max }`.
- Choice fields: `text`, `cost` (money paid first via SpendCred), `odds` (base % for good, default 50), `sure = true` (no roll, good), `ready = true` (chance from Readiness), `good` / `bad` outcomes, optional `rare` outcome + `rareOdds` (rolled first).
- Outcome fields: `key`, `headline`, `tone` ("win"|"loss"), `text`, `line` (his reply bubble), `note`, deltas `money aura followers placements hits sponsors xp`, `sponsor = "<id>"|"drop"`, `plant = { id, at = {lo,hi}? }`, `cooldown = n` (artist cooldown, visits), `disco = "trackone"` (discography kind for a placement; 8 outcomes, l.1937-2002).
- Follow-up shape: `{ id, visitor, tag, line, source?, resolve = { odds, good, bad }, choices? }` (`resolve` = the news rolled on arrival; `choices` = optional new offer).

Phone example (sure + ready, D l.1638): `two_sessions` has `needs = { visits = 10 }, cap = { group="sessions", per="week", max=2 }`, a `sure` choice with `xp = 40` and `plant = { id = "payback_homekid", at = { 10, 16 } }`, and a `ready = true` choice.

Plant path: `WI.apply` (l.248) -> `Rules.Plant(st, o.plant, W.FollowupAt, rngFor(uid), { sponsor = item.sponsor })` (Rules l.163):
```lua
local at = plant.at or defaultAt
local entry = { id = plant.id, at = state.count + rng(at[1], at[2]), ctx = ctx }
table.insert(state.queue, entry)
```
Returns nil when that id is already in `state.queue` (no duplicates). Default delay `Config.WalkIns.FollowupAt = {2,4}` walk-in visits (count-based, not time); `DropAt = {1,1}` for sponsor_drop. Queue entry = `{ id, at (absolute walk-in count), ctx = { sponsor } }`. Due when `q.at <= state.count + 1` (Rules `dueEntry`, lowest `at` first, filtered by follow-up `source` and `opts.exclude`). Due follow-ups beat cards in `Rules.Pick`. A follow-up whose id is `source="phone"` is not planted if `Config.Phone.Enabled == false` (WI l.268). System plants: `WI.PlantSystem(p, id, at)` (l.633; refuses if already seen ever or queued; before first walk-in adds +1 via `Rules.AfterFirst`); first HIT plants `mom_plaque` at {1,2}; sponsor_drop planted on arrival when Aura < sponsor floor. Phone plants go through the same queue (Ph.apply l.160 -> `Rules.Plant`; phone DOES plant, so a phone card outcome with `plant` queues a follow-up that Ph or WI delivers by its `source`).

`needs` gate: `Rules.GateOk(card, career, visits)` (l.192). Gateable keys are exactly `CAREER_GATES = aura, followers, placements, hits, sponsors, money` plus `visits` (= walk-in count `st.count`). `needs[k]`: have >= n; `under[k]`: have < n. Unknown key or missing value = never eligible. Cap: `Rules.CapOk` / `CountCap` use `state.caps[group] = { key, n }` with day/week keys from `Rules.CapKeys(now)` (whole UTC days since epoch, and day//7), counted at arrival (WI) or at phone open.

## 2. Roll and apply

- Chance: `Rules.Chance(base, career, odds)` (l.12):
  `aura = clamp(floor(career.aura / odds.auraPer), -auraCap, auraCap)`; `followers = min(floor(career.followers / odds.followersPer), followersCap)`; `result = clamp(base + aura + followers, odds.min, odds.max)`. Config `Config.WalkIns.Odds` (Config.lua): `auraPer=20, auraCap=15, followersPer=1000, followersCap=10, min=10, max=90`. So tilt is -15..+25, final 10..90.
- `Rules.ChoiceChance` (l.29): `ready` choices use `Readiness` (avg of level/placements/followers/aura each vs `Odds.ready = {level=7, placements=5, followers=30000, aura=600}`, capped at 1, negatives as 0) mapped onto min..max. `Rules.RollChance` (l.40): 100 if `sure`.
- `Rules.Resolve(choice, career, odds, rng)` (l.56): refuses `{ok=false, reason="afford"}` if `career.money < cost`; rare first (`rng(1,100) <= choice.rareOdds`), sure -> good, else `rng(1,100) <= chance` -> good else `choice.bad or choice.good`. Returns `{ ok, outcome, roll ("rare"|"sure"|"good"|"bad"), chance, deltas }`, deltas = `{ cost, money, aura, followers, placements, hits, sponsors, xp }` (raw). `Rules.ResolveNews(followup, ...)` (l.74) rolls `followup.resolve`.
- RNG: injected `rng(lo,hi)`. Server: `rngFor(uid)` in WI l.134 and Ph l.80 = Studio-forced `SetRng` list first, else `drawRng:NextInteger(lo,hi)` (`Random.new()`). Separate `timeRng` for delays. No seeded RNG, nothing stored.
- Apply (walk-in): `Choose` (WI l.513) -> `ctx.Data.SpendCred(cost)` -> `apply(p, res, item, cost)` (WI l.248): money via `ctx.Data.AddCred(p, n, "WalkIn")` / `TakeCred`; for each of `CareerRules.STATS` (aura, followers, placements, hits, sponsors): `Career.Add(p, stat, n, "WalkIn")` (gated, returns amount actually paid) or `Career.Take`; `sponsor` -> `Career.SetSponsor` + Life event; placements>0 -> `life(p,"placement",{v,key,disco})`; plant; `cooldown`. NO xp for walk-ins (header says so). Phone apply (Ph l.160): only aura/followers (others reported and ignored), money never applied (cost only), `xp` via `ctx.Data.AddXP(p, d.xp, "Phone")` (Config.XP.Sources.Phone max 60, dailyMax 3). Gates: `Config.Career.Sources.WalkIn` = aura max500/followers max20000, dailyMax 16, placements/hits/sponsors max 1 dailyMax 8; `Config.Cred.Sources.WalkIn` max 2000 dailyMax 16; `Sources.Phone` aura max 60, followers max 2000, dailyMax 7. `disco` on 8 outcomes (D l.1937-2002; corrected by the builder check 11-05), no walk-in "disco" stat.
- There is no `mood`, no stored roll history, no inventory/beat reference field on outcomes.

```lua
string.gsub(text, "{name:([^}]+)}", function(id) return names and names[id] end)   -- {name:<visitorId>}
string.gsub(out, "{sponsor}", ...)                                                    -- only if sponsorName
```
Unknown tokens stay literal. In WI, `filler(sponsorId)` (l.173) returns `fill(text)` with roster `NAMES` and `SponsorName`; applied to `tag`, `line`, choice `text`, outcome `headline/text/line/note`, and the visitor's display name (`newRecord` l.345). Sponsor id source: `item.sponsor or entry.ctx.sponsor or Career.Get(p).sponsor`. Phone uses `WalkIns.Filler`. NO `{artist}`, `{beat}`, `{bpm}`. Note `D` has a spec that every "$N" in a choice's text equals its `good.money` or `cost`.

## 4. Scheduler (WI) and Config.WalkIns

`Config.WalkIns` (Config.lua): `Enabled=true, Roster="parody", DailyMax=8, FirstDelay={60,120}, Gap={240,360}, ExpireSeconds=300, ExpireBusySeconds=90, WaitLineSeconds=45, MaxWalking=3, ArtistCooldown=3, FollowupAt={2,4}, DropAt={1,1}, Odds={...}, Rush={ Chance=0.15, Size={2,3}, Short={10,20} }`, plus ArriveDistance, WalkSpeed, WalkTimeout, TagSeconds, Spawn, Waypoints.

Flow: `loop()` (WI l.686) every 1 s: `upkeep` per in-flight visit, then (unless `paused()`) `tick(p)` (l.605). `tick`: `remaining[uid]` (server-memory seconds, nil until first hub entry -> `between(W.FirstDelay)`); counts down only when `inHub(p)` (Rules.InHub), no `pending[uid]`, and `PhoneBusy` not set; at 0 -> `schedule(p)` (l.561). `schedule` refuses (returns false, timer stays 0 and retries each second) when: `pending[uid]`, `PhoneBusy == true`, not in hub, `not Tour.State(p).done`, `not cypherIdle()`, or `Rules.CanSchedule(st, utcDay, DailyMax)` false. Else `nextPick` and queue to `waiting`; `pump()` admits via `Rules.Admit` up to `MaxWalking` server-wide.
Next-gap function: `nextGap(p, allowStart)` (WI l.368) -> `Rules.RushGap(rush[uid], W.Rush, W.Gap, draw, roll, allowStart and not held() and Rules.RushRoom(...))` (Rules l.142): normal gap = `draw(Gap)` (240-360 s of in-hub presence); 15% chance after a choice to start a burst of 2-3 with `Short` 10-20 s gaps, quiet gap afterwards adds back the saved seconds. At `st.today >= DailyMax` it ends rush and re-arms plain Gap. Called after Choose, Walk Away, errors, endVisit (and with `allowStart=false` when no pick exists). Player attribute `BusyDay` true during a burst. Burst state lives in memory only.
Storage in `prof.walkins` (`state(p)` WI l.148 repairs on every touch): `{ day = yyyymmdd UTC, today = visits today, count = lifetime walk-in count, queue = {{id,at,ctx}}, seen = {[cardId]=n}, last = {[visitorId]=count}, caps = {[group]={key,n}}, next = {kind,id} (stored pick), phone = { day, today, count } }`. `Rules.Rollover(state, today)` resets `today` when `day` differs (called in `CanSchedule` and `onArrive`). `utcDay()` = `ctx.Data._day()`.
Holds/pauses:
- `WalkInsPaused` attribute on `ReplicatedStorage.OK`: Studio only. `paused()` = attribute `== true` (skips `tick` entirely, also in Phone/Life loops). `held()` = attribute present at all (no bursts, no heal, Life's day loop skipped). Hook command `Pause` sets it (WI l.793).
- Cypher hold: `cypherIdle()` (WI l.116) reads `RS.OK.Cypher` attribute `Phase`; nil or "idle" = idle; checked in `schedule` and `DueWithin`.
- Phone DM open hold: player attribute `PhoneBusy` (set by `Ph.setBusy` l.123 while an opened DM awaits a choice). `tick` does not count down while set, and re-arms a timer already at 0 via `nextGap` so a DM close cannot instantly fire a visit; in a burst the timer is floored at `Rush.Short[1]`.
- Beat maker open: no server hold on scheduling. The visit still comes; client `WalkInUI` (l.391-396) defers the arrived card behind a chip while the beat maker/cutaway is open (`dawOrCutaway()`), a cypher is busy, or a phone card shows, and tells the server `WalkIn_Deferred(token, bool)` -> `setDeferred` (WI l.488). While deferred, his bubble says a `W.WaitLines` line every `WaitLineSeconds` (45 s) (`upkeep` l.674). Card expires after `ExpireSeconds` (300; 90 when others wait for a slot); expiry leaves a note card ("<NAME> LEFT") and the visit stays counted.
- Also gated on `Tour.State(p).done` (tour finished or skipped) and `Config.WalkIns.Enabled`.
Daily Aura heal also lives in this loop (see Q9).

## 5. Phone (Ph)

Config.Phone: `Enabled=true, DailyMax=6, FirstDelay={90,150}, Gap={120,180}, MaxWaiting=2, ExpireSeconds=600, OpenExpireSeconds=300, NewsCloseSeconds=8, WalkInDueSeconds=60, Layout="phone"`.
- Timer `remaining[uid]` armed with `between(P.FirstDelay)` on the first eligible tick (`tick` Ph l.377). `eligible(p)` (l.369): tour done, cypher idle, `not WalkIns.Busy(p)`, `not WalkIns.DueWithin(p, WalkInDueSeconds)`, no `PhoneBusy`, and `canSend(p)` (l.359): `unopened < MaxWaiting` AND `st.phone.today + unopened < DailyMax` (after `Rules.Rollover(st.phone, day)`). Timer counts only in eligible time. Phone works anywhere (not hub-gated). At 0, `schedule(p)` (l.345): `Rules.Seed` + `Rules.Pick` with `opts.source = "phone"`, `exclude` = all pending ids, then `remaining = between(P.Gap)` whether or not a pick; `sendPop` -> remote `Phone` ("pop", PopPayload) and `Rules.MarkSent` (artist cooldown across both sources).
- Data: same `W.Cards`/`W.Followups`, filtered by `source = "phone"` (NOT a `phone = true` flag, not a separate list). A pending pop `e = { token, id, kind = "dm"|"news", item, entry?, fill, sentAt, openedAt?, opened }` in `pending[uid]` (memory only; lost on leave/respawn/reset; not saved).
- Counts at OPEN: `open(p, token)` (l.208, remote `Phone_Open`): follow-up must still be in queue (`TakeQueued`), `st.phone.today/count += 1`, `st.seen[id] += 1`, `CountCap`. DM -> `setBusy` (PhoneBusy). NEWS (card `news=true` or any follow-up) applies immediately (`Resolve(choices[1])` or `ResolveNews`) and sends "result".
- Choose: `Ph.Choose(player, token, index)` (l.240, remote function `Phone_Choose`): index 0 = dismiss (removes entry, clears busy, telemetry CardWalkAway, stays counted); else same `Rules.Resolve` against `careerOf(p)` (level from prof.level), SpendCred for cost, `deliver()`, `CardChoice`/`CardReady` telemetry. Returns `{ok, result}` or `{ok=false, reason = stale|invalid|afford}`.
- Expiry sweep: un-opened after 600 s, opened DM after 300 s (as dismiss); `sweep` l.273.

## 6. Saved beats (DAW)

`prof.daw` (DAW.lua l.50-63) = `{ v = 2, slots = { s1 = {...}, s2, s3 }, active = <1..3>, saves = <total count> }`. Slot keys are strings via `DAW.SlotKey(n)` = `"s"..n` (DAWConfig `C.Slots = 3`). Slot record written at DAW l.158:
`{ pattern = <128-char string>, bpm, swing, kit = <id or nil if "studio">, voice = <id or nil if default> }`.
Pattern: DAWConfig `C.Version = 3`, `C.Length = 128` (80 drum chars = `#Tracks*16` + 48 keys chars), validated by `DAW.Validate` (per-track alphabets). BPM `C.BPM = { Default=142, Min=60, Max=200, Step=5 }`. There is NO name, NO stars, NO saved-at timestamp, NO brief id on a slot. `saves` is a global counter only.
Save remote `DAW_Save(pattern,bpm,swing,slot,kit,voice)` (l.~140-178): cooldown `Cfg.SaveCooldown = 3`, rejects empty (0 hits). `BeatSave` XP check (l.165-172): `nHits >= 4 and changed >= 4 (DAW.CellsDiffer(prev slot pattern, p)) and not prof.xpLog.paid[p]` (pattern not already paid today; `xpLog.paidDay` yyyymmdd resets `paid`) then `ctx.Data.AddXP(player, Cfg.XPPerSave (10), "BeatSave")`; Config.XP.Sources.BeatSave `{ xp = 10, cooldown = 60, dailyMax = 5 }`. Also fires Life event "beat" (first only) and `Saved(player, slot)`.
Brief linkage: none. `Contracts.Deliver` takes the pattern as a remote argument (not a slot); it sets `prof.sessions.last = p` (the last delivered 128-char pattern only, used for copy detection) and records no slot index. ## 9. Aura

- `CareerRules.Clamp(stat, value)` (CareerRules l.10): `math.floor(value)`; aura has NO min and NO max (unbounded both ways); every other stat `math.max(0, v)`. Used in `Career.Add` (gated gain) and `Career.Take` (no gate; Aura may go negative) and the hook Set path.
- Daily heal: `Config.Career.Sources.AuraHeal = { aura = { max = 5, dailyMax = 1 } }`. `CareerRules.HealAmount(aura, max)`: if `aura < 0` then `min(max, -aura)` else 0. ## 11. Tour (`RS/Systems/Tour.lua`, client `Modules/TourUI.lua`)

State `prof.tour = { got = { [stepId] = true }, done = bool, skipped = bool }`. Steps `M.Steps` (id, text, target): `open` "Open the studio PC or a studio laptop", `take` "Take the starter request from JUNO VALE", `deliver` "Make every ask tick green, then press DELIVER", `monitors` "Press ON MONITORS so the room hears it", `gear` "Spend your money at the gear rack" (5 steps; TourUI default total fallback 4). Any order; tracker points at first unfinished. Advance sources (`Tour.Init`): `DAW.Opened` -> open, `Contracts.Picked` -> take, `Contracts.Delivered` -> deliver, `Gear.Bought` -> gear, `DAW.BroadcastTried` (ok, or reason inline/full/cypher) -> monitors.
"New" detection: there is no `isNew` field. `prof.tour` absent or `done ~= true` = tour still active (the card shows on join via `send(p)`); `state()` creates the table lazily. Not versioned in the schema migration.
Ends: all five `got` -> `t.done = true`, `ctx.Data.GrantXP(player, M.RewardXP = 50, "Tour")` and Toast "Studio tour complete · +50 XP"; or Skip: remote `Tour_Skip` -> `Tour.Skip` sets `done = true, skipped = true`, no XP. Walk-ins and phone wait on `Tour.State(p).done` (done OR skipped).
`TourAdvance` is a Studio-only test hook command in `ServerScriptService/OK/Main.server.lua` l.26: `if cmd == "TourAdvance" then return require(RS.OK.Systems.Tour).Advance(p, a) end` (via `_StudioTestHook` BindableFunction), as is `ResetTour` (`Tour.Reset`). Real code calls `Tour.Advance(player, id)` directly.

## 12. HUD, toasts, hints

- Toast: client `panel.Toast(text)` (`Modules/PanelUI.lua` l.494): sets the bottom-centre `Toast` label, visible 2.5 s, replaced by the next. Server sends it as `RS.OK.Remotes.InteractionEvent:FireClient(player, "Toast", { text = ... })`; `ClientMain.client.lua` l.120 routes `kind == "Toast"` to `panel.Toast`. (Used by Tour, heal, FIRE, Life ribbons, DAY toast.) The HUD module itself has no Toast function.
- Banner: `hud.Banner(text)` = `C.Banner` (`Modules/HUD.lua` l.316): queued text label "LevelUp" (OK_LevelUp ScreenGui, DisplayOrder 10), 3.5 s each, one at a time, held (hold=true) while a walk-in/result/phone card is showing; `C.LevelUp(level, unlockText)` shares the queue and is never held. Server fires `InteractionEvent "LifeBanner", {text, tier}` -> `ClientMain` `lifeBanner(text)` (l.109) -> `hud.Banner`. `gui` attribute `BannerLog` holds the last 6 shown.
- Float: `C.Float(text, stat)` for stat changes (HUD watches Aura/Followers/etc. attribute changes and floats the delta); `hud.Float("+N XP")` etc.
- Hint / first-time explainer: none. grep for hint/explain/tip/FirstSeen/onboard finds only `DAWUI` `Hint` label (`C.SetHint(text)`, a static line under the beat maker, not once-only), `CardFeel.Footer()` (an Aura-band line on the walk-in/phone card), `Funnel.lua` (analytics onboarding funnel only), and the card `seen` flag in WalkInUI (not persisted). The only once-ever persisted flag-like state is `prof.tour`, `prof.life.firsts`, `prof.walkins.seen[cardId]`. A new "first-time explainer" mechanism would need a new prof table (a v6 field).

## 13. Schema and migration (`ServerScriptService/OK/Services/DataService.lua`)

`M.SchemaVersion = 5` (l.39). `Config.Data` holds only lock settings (`LockStaleSeconds, LockHeartbeatSeconds, LockWaits, UseStoreInStudio`); schema number lives in DataService. Saves via UpdateAsync with `prof.v = math.max(prof.v, SchemaVersion)` (l.318); a stored profile with `v > SchemaVersion` is loaded but never saved (l.240). `M.migrate(prof)` (l.101) runs on every load, and also for new/detached profiles. Pattern, v4 and v5 pieces:
```lua
-- shapes written out here so DataService needs no system module
local function newCareer() return { aura = 0, followers = 0, placements = 0, hits = 0, sponsors = 0, sponsor = nil, showSponsor = true, gates = {}, careerLog = {} } end
local function newWalkins() return { day = 0, today = 0, count = 0, queue = {}, seen = {}, last = {} } end
...
if prof.v < 4 then prof.career = newCareer(); prof.walkins = newWalkins(); prof.v = 4 end
-- a career or walkins that is not a table (hand-edited or corrupt store) is replaced whole
if type(prof.career) ~= "table" then prof.career = newCareer() end
if type(prof.walkins) ~= "table" then prof.walkins = newWalkins() end
prof.xp = tonumber(prof.xp) or 0 ... prof.level = M.LevelFor(prof.xp)
-- after the repairs and the level above: the backfill reads a whole career and a current level
if prof.v < 5 then prof.life = newLife(prof); prof.v = 5 end -- the career remembers
if type(prof.life) ~= "table" then prof.life = newLife(prof) end
return prof
```
v6 recipe: write `newXxx(prof)` near `newLife`; bump `M.SchemaVersion = 6`; add `if prof.v < 6 then prof.xxx = newXxx(prof); prof.v = 6 end` after the v5 line (backfill AFTER the level/career repairs), plus an `if type(prof.xxx) ~= "table"` repair line. Also: `M.ClientProfile(prof)` (l.~150) strips `prof.life` from the client copy, so a large new table should be stripped there too; sub-fields inside existing tables (`prof.walkins.phone`, `.caps`, `prof.sessions`, `prof.tour`, `prof.daw`) are NOT versioned: they are defaulted lazily in their system's `state()` (WI l.148, Contracts l.24, Tour l.27, DAW `Migrate` l.57), so adding a field to those needs no schema bump ("schema v4 unchanged: this is the one place they are filled in"). Spec/test pins: the Config.Life literal copy in `spec/economy_fixture.lua`; tests check `SchemaVersion` (grep spec/ and build/ for "SchemaVersion" before bumping; not inspected here).
